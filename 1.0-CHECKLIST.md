# Avleon 1.0 Readiness Checklist

As of 2026-09-24

Avleon is not ready for 1.0: core has open security holes in auth, validation and file storage that must close first, followed by correctness bugs, CLI fixes, packaging, tests and docs. Items come from read-only audits of `core/`, `cli/` and `docs/`; paths are relative to each repo.

## P0: Security (release blockers)

Each of these is exploitable in a default app and blocks the release.

- [x] **`@Authorized` fails open.** With no authorizer registered, the route is served unprotected. An authorizer that returns `false` is ignored and has to throw instead. Make it deny by default and treat `false` as 403. (`core/src/core/router.ts:143-155`, `332-369`)
- [x] **Handlers get the raw body and query, not the validated DTO.** Pass the `plainToInstance` result through and add `whitelist` / `forbidNonWhitelisted` (mass-assignment risk). Fix the validation error message, which is always `undefined` because `err` is an array, and align its shape with the error handler. (`router.ts:396-441`, `validation-utils.ts:89`)
- [x] **Storage path traversal through a sibling prefix.** `startsWith(baseDir)` has no trailing separator, so `to: "../public-evil"` passes. Use `path.relative` or `baseDir + path.sep`, and validate `to`. (`storage/file-storage.ts:109, 179, 233`)
- [x] **Storage reads are not confined.** `getUploadFile`, `download` and `downloadAs` open any path they are given. Confine them to `baseDir` and handle missing files. (`file-storage.ts:57-83`)
- [x] **Uploads overwrite by default into `public/`.** An upload named `index.html` can replace served content (defacement or stored XSS). Randomize filenames, default `overwrite: false`, add MIME and extension allowlists, and enforce `maxFileSize`. (`file-storage.ts:42, 90, 101, 166`)
- [x] **Path traversal in `UploadFileFromRequest`.** The write path is built from the client's filename. (`core/src/http/multipart.ts:87-100`)
- [x] **`Content-Disposition` header injection** from an unsanitized filename. (`router.ts:461`)
- [x] **Credentials logged.** `console.log("datasource", dataSource)` dumps the whole DataSource, including credentials. (`data/collection.ts:403`)
- [x] **Internals exposed in production.** `isDevelopment()` treats an unset `NODE_ENV` as dev, while the error handler requires `"development"`, so docs get exposed when `NODE_ENV` is unset. Use one definition and stop echoing `error.message` and raw `payload` in production. (`core/application.ts:597, 795-800`)
- [x] **Race on `FileStorage` transform state.** The singleton keeps `transformOptions` as instance state, so request A's transform can land on request B's file. Pass the options per call. (`file-storage.ts:40, 53, 303`)

## P1: Core correctness

These are advertised features that crash or silently misbehave. Paths are under `core/src/`.

**HTTP and app**

- [ ] **`useScheduler({path})` crashes `run()`.** It requires `../schedule-registry`; the correct path is `../scheduler/schedule-registry`. (`core/application.ts:738`)
- [ ] **`@UploadFile` / `@UploadFiles` throw.** `saveRequestFiles()` is async but not awaited. (`core/router.ts:540`)
- [ ] **Non-400 framework errors become 500.** Respect `error.statusCode` for 401, 413, 415, 429 and the rest. (`application.ts:800`)
- [ ] **No way to set a status code.** `Results.NotFound` / `NoContent` and `HttpResponse.Created` don't set status, and `OkStream` is empty. Make the router honour them or add `@HttpCode`. (`http/results.ts`, `http/response.ts:55`)
- [ ] **`@All` throws at registration.** Fastify rejects the `"ALL"` method.
- [ ] **Built-in `Validator` rejects `0`, and `min` / `max` / `exact` / `optional` are ignored.** (`http/validation.ts:79, 92`)
- [ ] **Missing decorator metadata crashes.** Without `design:paramtypes` (tsx, esbuild, SWC), `getDataType(undefined)` throws. Parameter names are parsed from `Function.toString()`. (`validation-utils.ts:29`, `params.ts:61-63`)
- [ ] **Middleware order is inconsistent.** Global middlewares run before authentication, while `@UseMiddleware` runs after authorization. `@UseMiddleware` also calls `new middleware()` at decoration time, which bypasses DI. (`router.ts:371`, `middleware.ts:144`)
- [ ] **Metadata cache keyed on `constructor.name`.** Same-named classes collide. (`router.ts:162`, `application.ts:645`)
- [ ] **Controller path handling.**
    - `_resolveControllerDir` ignores its argument and replaces the first `src` anywhere in the absolute path. (`application.ts:621, 740`)
    - `useControllers([...])` overwrites earlier calls.
    - `getApp(options)` ignores options after the first call.
- [ ] **Functional routes are incomplete.** `mapGet` / `mapPost` / `mapPut` / `mapDelete` have no `mapPatch` and get no auth, DI params or error shape. `useMiddleware` passes an unbound `invoke`. (`router.ts:629`)
- [ ] **`run()` binds localhost only.** Add a `host` option and default to `0.0.0.0` in containers. (`application.ts:888`)
- [ ] **Graceful shutdown doesn't close anything.** Call `app.close()` and close TypeORM, Knex, Redis and Socket.IO with a drain timeout instead of calling `process.exit(0)` directly. (`application.ts:880-886`)
- [ ] **`PartialType` / `OmitType` / `PickType` don't work with class-validator.** Validators aren't made optional, and `OmitType` returns an empty class. (`helpers/map-types.ts`)
- [ ] **OpenAPI output is broken.**
    - Component schemas are never generated, so nested DTO `$ref`s dangle. (`swagger-schema.ts:316-321`)
    - Schema generation runs `new classType()` and lists prototype members.
    - Scalar `spec.content` returns the plugin module, not the spec. (`application.ts:395`)
- [ ] **`Environment` rereads `.env` on every `get()`,** and `dotenv.config()` runs as soon as the package is imported. (`environment-variables.ts:17, 57-89`)

**Data**

- [ ] **Query operators are undefined at runtime.** `Like`, `In`, `Not` and the rest are re-exported as types only. (`data/typeorm-provider.ts:2-55`)
- [ ] **`AvleonRepository.transaction()` runs outside the transaction** for `@Repository` classes. (`typeorm-provider.ts:325, 398-400`)
- [ ] **`useTypeORM` never sets the `"idatasource"` token,** so `Collection.fromRepository` and `@InjectRepository` fail. (`collection.ts:401, 466`)
- [ ] **Collection bugs.** `paginate` slices the wrong range, `min()` uses `Math.max`, `findAsync` ignores its predicate, and `prev` is computed like `next`. (`collection.ts:189, 353, 370, 425`)
- [ ] **Knex hooks are dead.** There's no setter, and the code requires `DB`, which isn't exported (it's `KnexDB`). Fix them or remove them. (`application.ts:153-161, 711-729`)
- [ ] **Three incompatible pagination APIs.** Unify them into one.
- [ ] **`@Queue` and `@Repository` break constructor injection in subclasses.** (`queue.ts:311`, `typeorm-provider.ts:397`)

**Queue, scheduler, events and cache**

- [ ] **`@Queue` always starts a worker.** Add a producer-only mode. `@AvleonWorker` starts on import, before config and DI are ready. (`queue/queue.ts:318`, `queue/worker.ts:109-112`)
- [ ] **Socket handler errors become unhandled rejections** and can crash the process. (`events/event-subscriber.ts:79`)
- [ ] **Scheduler decorators mutate the parent class's task list.** Use `getOwnMetadata` plus a copy. Remove the node-cron v3 `scheduled` option. (`schedule-decorator.ts:65, 91, 119`, `scheduler.ts:131`)
- [ ] **Events.**
    - Listeners are keyed by class name.
    - `once` listeners can fire twice or be dropped.
    - `queue: true` ignores `delay`.
    - Failed jobs are lost.
    - (`events/event-registry.ts`)
- [ ] **The in-memory cache ignores TTL, so it grows without bound.** Redis tag sets never expire, and all state is static. (`observability/cache.ts`)
- [ ] **The logger always uses the pino-pretty transport.** Use JSON in production and wire the logger into Fastify. (`observability/logger.ts:9-16`)

## CLI (`@avleon/cli`)

Several documented flags and aliases don't work, and the generated code doesn't always compile. Paths are under `cli/src/`.

- [ ] **Replace the hand-rolled `args.some(...)` parsing** with commander, cac or yargs. That fixes the next four items at once.
- [ ] **Add `--help`, `-h`, `--version` and `-v`,** plus help for each command. Today they print "Invalid command".
- [ ] **`-m` means two things:** `--minimal` for `new` and `--model` for `make:*`. It is parsed globally. (`cli.ts:242`)
- [ ] **`m:cfg` and `m:mdlr` are rejected.** They are missing from `commandList`. (`commands.ts`, `cli.ts:264, 268`)
- [ ] **`new --minimal` is ignored.** `createApplication` never reads `flags`. (`create.ts:479`)
- [ ] **`new` overwrites an existing directory.** Refuse unless the directory is empty or `--force` is passed. (`create.ts:492-567`)
- [ ] **`-f` is ignored for controllers and services,** which always overwrite. `-m` also overwrites an existing service. (`controller.ts:81, 97`, `service.ts:59`)
- [ ] **`m:c product -m product -r` generates code that doesn't compile.** Generate the model too, or skip the import. (`stubs/services/rest-service.stub:2`)
- [ ] **Name casing is broken.** `JwtAuth` becomes `JwtauthConfig` and `UserProfile` becomes `Userprofile`. Use one casing helper and one file-naming convention (`.model.ts`, `.service.ts`, `.controller.ts`, all kebab-case). (`cli.ts:174`, `controller.ts:8-11`, `helpers/file-helper.ts:23`)
- [ ] **`getAvleonVersions` reads the wrong `package.json`,** so new projects always get `"latest"`. Pin real versions. (`create.ts:63`)
- [ ] **Errors exit with code 0.** Exit non-zero and drop the `node artisan` wording. (`cli.ts:76, 170, 347-349`)
- [ ] **Importing the package's main entry runs the CLI.** Split the bin entry from the library entry. (`cli.ts:351`, `index.ts`)
- [ ] **Project root detection.** Find the project root instead of writing relative to `cwd`, and build paths with `path.join`, not string concatenation, for Windows (`admin\User`). (`controller.ts:65`, `service.ts:41`, `file-helper.ts:3, 11`)
- [ ] **`build`.** Check that `tsconfig.build.json` exists, drop the unused `NODE_ENV`, and copy non-TS assets. (`cli.ts:253-258`)
- [ ] **`serve`.**
    - Type-check the code.
    - Copy assets.
    - Watch `.env`.
    - Honour tsconfig `paths`.
    - Debounce `add` events.
    - Handle SIGTERM.
    - Fix the `dist/server.js` vs `dist/serve.js` fallback.
    - Don't keep stale JS running after a failed compile.
    - Shut down gracefully on Windows.
    - (`serve.ts:14, 209, 297, 333-342`)
- [ ] **Move inline templates into stubs.** `create.ts:179-311` duplicates the unused stub files, and the config and middleware templates are inlined in `cli.ts:143-198`.

## Packaging and release

The CLI can't publish a new version as it stands, and both packages have metadata that breaks consumers.

**core**

- [ ] Add `rimraf` to devDependencies, or replace it with `node -e fs.rmSync`. The build script uses it.
- [ ] Add an `exports` map, an ESM build (or a documented CJS-only decision) and a `sideEffects` field. Today `main` and `module` both point at CJS.
- [ ] Stop exporting `mock-db` from the public index. Its `.d.ts` needs `jest` types. Also build without `types: ["jest"]`.
- [ ] Fix the license mismatch: `package.json` says ISC but the `License` file is MIT, and `files` lists `LICENSE` while the file is named `License`.
- [ ] Move optional features (socket.io, `@fastify/*`, Scalar, bcryptjs, pino-pretty) to optional peer dependencies, and use one loader for them.
- [ ] Declare `class-validator` and `class-transformer` as peer dependencies.
- [ ] Decide what to do about typedi, which is unmaintained and has no request scope: replace it or vendor a container.
- [ ] Fix the tooling: `jest.config.js` and `eslint.config.js` use ESM without `"type":"module"`, lint-staged calls `pnpm` and `cross-env` in an npm repo, and husky 8 is deprecated. Turn off `collectCoverage` by default.
- [ ] Remove the unused devDependencies `tsdown` and `unplugin-unused`.

**cli**

- [ ] **Fix the publish workflow.** It tags a new version on every push but never bumps `package.json`, so it republishes 0.0.47. Publish from a tag or release with a test and lint gate. (`cli/.github/workflows/publish.yml`)
- [ ] **chalk 5 is ESM-only and loaded with `require`.** It breaks on Node 18 and on Node 20 before 20.19. Drop chalk (the code already hand-rolls ANSI codes) and add `engines: >=20`.
- [ ] **`types: dist/index.d.ts` doesn't exist.** Remove the field or emit declarations.
- [ ] **`@avleon/core` is both `*` in dependencies and `>=0.0.38` in peers.** Keep one.
- [ ] Replace lodash with small helpers. Make `prettier` optional or drop it. Move `rimraf` to devDependencies. Remove `@swc/cli`, `tsup`, `concurrently` and `nodemon`.
- [ ] Add a LICENSE file. Remove the no-op `stubs` and `scripts` entries from tsconfig `include`. Rename `readme.md` to `README.md`.

**docs and repos**

- [ ] **The docs deploy runs `npm install` in a pnpm repo,** so the lockfile is ignored. (`docs/.github/workflows/deploy.yml:13, 18`)
- [ ] **Decide the release process across the three repos:** versioning policy, a changelog, and matching core and CLI versions.
- [ ] **Replace the "NOT FOR PRODUCTION" banners** in `docs/README.md`, `introduction.md` and `cli/readme.md`.

## Tests

Core has 219 passing tests in 21 suites, but the request pipeline and most runtime modules have none, and the CLI has no tests at all. Every P0 and P1 fix should land with a regression test.

- [ ] **Request pipeline over `inject`:** `@Authorized` (including fail-closed), DTO validation and whitelisting, `@UploadFile`, error handler status codes, and OpenAPI output. (`core/router.ts`)
- [ ] **`application.ts`:** `run()`, shutdown, controller auto-discovery, `useScheduler({path})` and swagger init.
- [ ] **Storage on a real temp directory,** not mocked fs, so it catches the sibling-prefix traversal and `to: ".."`.
- [ ] **No tests yet for:** events (registry, dispatcher, queue, socket dispatcher, subscribers), scheduler, `worker.ts`, `typeorm-provider` (repository, transaction, paginate), the Redis cache path, `testing.ts`, `results.ts`, `response.ts`, `map-types.ts`, config and exceptions.
- [ ] **Collection:** `paginate`, `min` and `findAsync`.
- [ ] **Fix hollow tests.** `tests/decorator.test.ts` has no assertions, `websocket.test.ts` is a placeholder, `cache.test.ts:37` misuses `resolves.not.toThrow`, and the logger tests only check constructor args.
- [ ] **Fix `AvleonTest`.**
    - `from()` doesn't await `_mapControllers()`, which is a race.
    - It replaces the production error handler.
    - `getController` mutates the global container.
    - (`testing.ts:68, 83`)
- [ ] **Add coverage thresholds** in `jest.config.js` and a CI job that runs tests and lint on every PR in all three repos.
- [ ] **Add CLI tests:** snapshot the generated files for each `make:*` command, check `new` against a temp directory, and test the argument parsing.
- [ ] **Reduce lint debt:** 128 ESLint warnings and about 283 `any` annotations. Turn `no-explicit-any` back on for the public types (`IRequest`, `GlobalOptions`, `use*` options, `IAvleonApplication`).

## Missing features

This split is a proposal: the first list is the minimum for a production-grade 1.0, and the rest can ship in 1.x. Move items between the lists as you decide scope.

**Proposed for 1.0**

- [ ] Security headers (helmet) and rate limiting, as first-party `use*` options
- [ ] Health and readiness endpoints
- [ ] Request ID and correlation ID in logs, with the Fastify logger wired and structured JSON in production
- [ ] Status and response control: `@HttpCode`, `@Redirect`, headers
- [ ] Exception filters, or a pluggable error handler, instead of the hard-coded one
- [ ] Lifecycle hooks (`onInit`, `onBootstrap`, `onShutdown`) so services can close their connections
- [ ] Config schema validation at boot
- [ ] Global route prefix and API versioning (URI or header)
- [ ] Compression
- [ ] Socket.IO handshake authentication that populates `socket.data.user`, and per-channel authorization
- [ ] A queue driver for tests (in-memory or sync)
- [ ] Producer-only queues (see P1)
- [ ] CLI: `start`, `route:list`, `doctor` (Node version, core version, decorator flags) and `make:dto`

**Candidates for 1.x**

- [ ] Interceptors, pipes and request-scoped DI (depends on the typedi decision)
- [ ] A module system (feature modules, providers, imports and exports)
- [ ] OpenTelemetry tracing and Prometheus metrics
- [ ] Link OpenAPI security schemes to `@Authorized`
- [ ] A storage driver interface with S3, GCS and Azure, signed URLs and range requests
- [ ] Cache: LRU and size limits, `remember` / getOrSet, a `@Cacheable` decorator, key namespacing
- [ ] Queue: DLQ abstraction, default retry and backoff, bull-board integration
- [ ] Distributed locks for the scheduler, so every replica doesn't run every cron
- [ ] A Redis adapter for Socket.IO, and a rooms and presence API
- [ ] Real Kafka and RabbitMQ event transports, and the fluent `Fire` event API from the design notes
- [ ] Migrations, seeders and factories, with `make:migration`, `db:migrate` and `db:seed`
- [ ] A `@Transactional` decorator or unit of work, and cursor pagination
- [ ] Mail and notifications
- [ ] CSRF, cookies and sessions, JWT strategy helpers
- [ ] i18n
- [ ] CLI: `make:event`, `make:listener`, `make:job`, `make:task`, `make:guard`, `make:test`, `make:resource`, `openapi:export`, `upgrade`
